# 01 · `miniagent/safety.py`:危险命令黑名单

**作用**:agent 能执行 shell 命令,这个文件在命令真正执行前做最后一道检查。命中任何一条规则就拒绝。它不能被 `-y` 绕过。

## 逐行

**第 1–2 行**:模块说明(docstring)。写在文件最开头的三引号字符串,Python 会把它当文档。

**第 3 行** `import re`:导入正则表达式标准库。

**第 5–16 行** `_DENY`:一个列表,每个元素是一个二元组 `(正则, 拦截理由)`。
- `r"..."` 前缀 `r` 表示"原始字符串":反斜杠不被当作转义,正则里全是反斜杠,所以几乎都要加 `r`。
- `list[tuple[str, str]]` 是类型标注:"元素是(字符串, 字符串)二元组的列表"。

正则里用到的符号:

| 符号 | 含义 |
|---|---|
| `\b` | 单词边界,保证 `sudo` 不会误匹配 `pseudo` |
| `\s` / `\s+` | 一个/多个空白字符 |
| `\S` / `\S*` | 一个/任意个非空白字符 |
| `( ... )*` | 括号里的内容重复 0 次或多次 |
| `a\|b` | a 或 b |
| `[rR]` | r 或 R 其中一个 |
| `[^|;&]*` | 任意个"不是 \| ; & 的字符"(用来限制在同一条命令内) |
| `$` | 字符串结尾 |
| `\.` `\$` `\*` | 把有特殊含义的符号当普通字符 |

每条规则:

1. **第 6 行** 递归删除危险目标。拆开读:`rm` + 若干选项如 `-f ` + 一个含 `r`/`R` 的选项(如 `-rf`、`-fr`)+ 若干选项 + 目标是 `/`、`~`、`$HOME`、`*`、`.`、`..` 之一 + 后面是空白或行尾。能拦住 `rm -rf /`、`rm -fr *`,不会拦 `rm -rf build/`(目标是 `build/`)。
2. **第 7 行** `sudo`。
3. **第 8 行** `mkfs` 或 `mkfs.ext4`(格式化磁盘)。
4. **第 9 行** `dd ... of=/dev/...`(往块设备写数据)。
5. **第 10 行** `> /dev/sda` 之类的重定向写磁盘。
6. **第 11 行** fork 炸弹 `:(){ :|:& };:`。
7. **第 12 行** `curl ... | sh`、`wget ... | bash`(下载后直接执行)。
8. **第 13 行** `chmod -R 777 /`。
9. **第 14 行** `git push --force` 或 `-f`。
10. **第 15 行** `shutdown` / `reboot` / `halt`。

**第 17 行** `_COMPILED = [(re.compile(p), why) for p, why in _DENY]`:
- 对 `_DENY` 里每一个 `(p, why)`,把字符串 `p` 编译成正则对象,得到新列表。
- `for p, why in ...` 叫**解包**:把二元组的两个元素分别赋给 `p` 和 `why`。
- 编译只做一次(模块加载时),之后每次检查更快。

**第 20–25 行** `check_command(command)`:
- 返回类型 `str | None`:命中返回拦截理由字符串,没命中返回 `None`。
- 第 22 行遍历每条规则;第 23 行 `pat.search(command)` 在命令字符串**任意位置**找匹配;命中就 `return why`。
- 全部没命中走到第 25 行,返回 `None`。

## 使用方

`tools.py` 的 `Workspace.bash`:`reason = check_command(cmd)`,有理由就抛 `ToolError`。

## 要知道的局限

这是黑名单:没列出来的危险写法都放得过去,比如 `python -c "import shutil; shutil.rmtree('/')"`。README 里也明确说明它只是纵深防御,真正的隔离要靠容器。
